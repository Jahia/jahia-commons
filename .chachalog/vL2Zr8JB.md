---
jahia-commons: minor
---

Added key rotation for encrypted values: each value records the key that sealed it, and earlier keys stay readable.

Set `jahia-commons.encryptor.previous.1`, `jahia-commons.encryptor.previous.2` and so on, or `JAHIA_COMMONS_ENCRYPTOR_PREVIOUS_1` and so on, to the earlier keys. New values are sealed with `jahia-commons.encryptor.password`. Earlier keys open values written by this version only. Values written before, which carry no format marker, are read with `jahia-commons.encryptor.legacy.password`, so set it to the password that wrote them, or to `__shipped__` when none was set. Startup is refused when earlier keys are set and that property is not. Once no stored value carries the earlier unmarked format, set it to `__none__` to stop reading that format.

On a cluster, add the new key as a read-only key on every node first. Once every node holds it, move it on each node from `jahia-commons.encryptor.previous.<n>` to `jahia-commons.encryptor.password`: a key named in both is refused at startup. Keep `jahia-commons.encryptor.legacy.password` set at that step, because without read-only keys its default follows the new password, and every unmarked value would then be read under the wrong key. The same two steps give a cluster its first key: a node with read-only keys and no primary key reads the values sealed under them, and still writes new values in the earlier format. Until `jahia-commons.encryptor.legacy.password` is set to `__none__`, a node rolled back after the second step goes back to the first one, with the key kept as a read-only key. Each passphrase, as the primary key or as a read-only key, is stretched once when the encryptor is built, which takes about half a second per key. Prefer a key of 32 random bytes, which costs nothing to build: `openssl rand -base64 32` produces one, set as `base64:` followed by its output. This version does not read values that version 1.2.0 sealed with a password of the installation's own.
